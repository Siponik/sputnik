# Напоминания в Telegram

В Google Tasks нет напоминаний, поэтому их ставит Спутник. Трекер складывает ближайшие напоминания в файл `sputnik-reminders.json` в папке «Спутник» на Google Drive. Скрипт `Code.gs` работает в Google Apps Script в твоём аккаунте: раз в минуту он читает этот файл и пишет боту. Работает, даже когда компьютер выключен, и ничего не стоит.

Перед отправкой скрипт проверяет задачу: если её уже выполнили или удалили (например, на телефоне), напоминание не придёт.

## Настройка (один раз, ~5 минут)

1. Открой https://script.google.com под тем же аккаунтом Google, что и трекер → **Новый проект**. Назови его «Спутник · напоминания».
2. Сотри всё в `Код.gs` и вставь содержимое файла `reminders/Code.gs` целиком. Нажми 💾.
3. Слева у **Сервисы** нажми **+** → выбери **Google Tasks API** → **Добавить**.
4. Слева ⚙️ **Настройки проекта** → внизу **Свойства скрипта** → **Добавить свойство** два раза:
   - `TELEGRAM_BOT_TOKEN` — токен бота (тот же, что в секретах GitHub);
   - `TELEGRAM_CHAT_ID` — твой chat id.
5. Вернись в редактор (`< >` слева), сверху выбери функцию **setup** → **Выполнить**. Google попросит доступ: «Проверить разрешения» → свой аккаунт → «Дополнительные настройки» → «Перейти к проекту» → «Разрешить».
6. В Telegram придёт «🛰 Спутник: напоминания подключены». Готово.

Выключить: выполнить функцию **stop**. Журнал запусков — слева **Выполнения**.

## «Входящие от Claude» (`Inbox.gs`)

Тот же проект Apps Script принимает задачи из чатов Claude (схема — `docs/claude-inbox.md`). Claude создаёт событие в календаре «Спутник · входящие» с JSON-запросом в описании. Каждую минуту `tick()` вызывает `inboxTick_()`: тот выполняет запрос в Google Tasks, пишет итог в служебное событие «Спутник · статус» (тот же календарь, 1 января 2030, JSON в описании; не на Drive, потому что Drive бывает переполнен) и удаляет событие. Если запрос с ошибкой, событие не удаляется, а получает в названии «⚠», и ошибка попадает в статус.

Подключение (один раз):
1. В проекте «Спутник · напоминания» нажми **+** у «Файлы» → **Скрипт**, назови `Inbox` и вставь содержимое `reminders/Inbox.gs`.
2. В `Код.gs` замени всё на свежий `reminders/Code.gs` (в нём `tick()` теперь вызывает и входящие). Сохрани.
3. Выбери функцию **setupInbox** → **Выполнить** и разреши новые доступы (Календарь). Придёт сообщение в Telegram.

## Как это устроено

- Правило напоминания хранится в слое Спутника (`tasks[id].remind`): «за N дней до срока в ЧЧ:ММ» или точное время.
- Трекер обновляет файл на Drive через несколько секунд после любого изменения. Если трекер закрыт, в файле остаётся последний список — уже поставленные напоминания всё равно придут.
- Напоминание, пропущенное больше чем на 12 часов, не отправляется.

## Утренняя сводка в Telegram (`morningTick_` в `Code.gs`)

По будням в 08:00 МСК скрипт шлёт ссылку на страницу сводки («🛰 Спутник · утренняя сводка готова» с кнопкой). Раньше это делал
GitHub Actions, но его расписание опаздывает и иногда пропускается (20.10 сообщение не пришло). Ссылка — свойство скрипта `BRIEF_URL`
(если не задано — страница «Спутник · Утро»). Проверить: выполнить функцию **testBrief**.
Когда скрипт обновлён, в GitHub выставлена переменная репозитория `BRIEF_VIA_GAS = true` — тогда workflow «Утренняя сводка»
по расписанию ничего не шлёт (остаётся ручной запуск).

## Команды боту (`Bot.gs`)

Время сводки можно поменять прямо в Telegram — написать боту:

- `/time` — когда приходит сводка; `/time 7:30` или просто `7:30` — новое время (по Москве);
- `/days будни` или `/days все` — только по будням или каждый день;
- `/off` — пауза, `/on` — включить снова;
- `/now` — прислать ссылку на сводку сейчас.

Бот отвечает в течение минуты: `tick()` раз в минуту забирает новые сообщения (без вебхука). Слушает только твой чат
(`TELEGRAM_CHAT_ID`), остальным не отвечает. Настройки лежат в свойствах скрипта `BRIEF_AT` (минуты от полуночи),
`BRIEF_DAYS` (`work` / `all`), `BRIEF_OFF`.

Подключать вручную не нужно: файл приезжает с автообновлением (ниже), а при первом запуске бот сам включает меню
команд и присылает сообщение с текущим временем (функция `setupBot`, свойство `BOT_READY`).

Синхронизация со сборкой: задача Claude «Утренняя сводка» собирает страницу по будням в 5:45 МСК и, опубликовав её,
ставит в календарь «Спутник · входящие» событие «Спутник · сводка готова» на сегодня. Бот шлёт ссылку в выбранное время,
но не раньше этой отметки. Если сводка за 3 часа после выбранного времени так и не собралась — придёт ссылка с пометкой,
что по ней прошлая сводка. В выходные сводку не собирают, поэтому при `/days все` в субботу и воскресенье по ссылке пятничная.

## Автообновление скрипта из GitHub

Вставлять код руками больше не нужно. После каждого слияния в `main`, где менялась папка `reminders/`,
workflow `.github/workflows/apps-script.yml` заливает `*.gs` и `appsscript.json` в проект Apps Script «SputnikNotification»
(id — в `reminders/.clasp.json`) через `clasp push --force`. Файлы в проекте заменяются целиком; свойства скрипта
и триггер `tick` остаются. Ручной запуск — Actions → «Apps Script» → Run workflow.

Настройка (один раз):
1. Открой https://script.google.com/home/usersettings и включи **Google Apps Script API**.
2. В PowerShell: `npx.cmd @google/clasp@3.4.1 login` (именно `npx.cmd` — `npx` PowerShell не даст запустить) — откроется браузер, войди тем же аккаунтом Google и разреши.
3. `Get-Content "$env:USERPROFILE\.clasprc.json" | Set-Clipboard` — содержимое файла скопируется.
4. GitHub → репозиторий → Settings → Secrets and variables → Actions → **New repository secret**: имя `CLASPRC_JSON`, значение — вставить.

Без секрета workflow ничего не делает (только предупреждение). Секрет даёт доступ к Google-аккаунту — нигде больше его не публикуй.
