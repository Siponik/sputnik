# Спутник — карта для Claude

Личные ссылки, адреса и id (почта, календарь-очередь, ссылки на холсты, проект Google Cloud, пути на компьютере) — **не здесь** (репозиторий публичный), а в `/mnt/project-files/private/sputnik-private.md`. Никаких ключей, токенов и личных данных в коммиты.

Пользователь — Siponik, дизайнер 3D и игрового арта, Windows, МСК, не программист. Общаемся по-русски, коротко, простыми словами; команды — готовыми для PowerShell. Не ждать впустую: если нужна сборка или действие пользователя — остановиться и сказать, что проверить.

## Проверки

- Логика, быстро (секунды после первой сборки): `cd rust; cargo test -p sputnik-core`
- Всё Rust: `cd rust; cargo test --workspace` (часовой пояс тестов — Москва; на Linux нужны `libfontconfig1-dev libxkbcommon-dev`)
- Запуск без Google: `SPUTNIK_DEMO=1 cargo run -p sputnik`
- Старый трекер и боты: `cd tracker; npm test` (тесты ботов `bot/` и `reminders/` пока лежат в `tracker/tests/` — при удалении трекера перенести)
- Новую чистую логику — сразу с тестом в `rust/core/tests/`.
- Экраны с картинками не сверять: пользователь смотрит вид сам в бете.

CI на PR: `rust-check.yml` (тесты Rust + проверка, что собирается под Windows) и `check.yml` (тесты трекера и ботов) — каждый только когда PR трогает свои папки. Сборка `sputnik.exe` — после слияния в `beta`/`main` (`rust-release.yml`): версия `0.1.<номер сборки>`, подпись ключом трекера, `latest.json` в служебном релизе `rust-latest`; приложение обновляется само. «Что нового» в Rust-сборке — названия коммитов, меняющих `rust/`, поэтому названия коммитов пишем понятными пользователю.

## Как работаем

1. Одна фича — один тред — одна ветка от свежей `beta` — один PR в `beta`. Даже если фича расписана по шагам.
2. PR небольшой (ориентир до ~800 строк). Большое — несколько PR подряд, каждый рабочий.
3. В PR — раздел `## Что нового` (1–3 пункта простыми словами, без файлов; шаблон — `.github/pull_request_template.md`).
4. Пользователь проверяет сборку беты → PR `beta` → `main`. В `main` — только проверенное.
5. Файл не больше ~600 строк: растёт — делим по разделам. Два треда не правят один раздел одновременно.
6. CLAUDE.md правим, только когда меняется карта или постоянное решение. Историю «что когда сделали» сюда не пишем — она в git и PR.

## Решения (не пересматривать без пользователя)

- Источник правды — Google Tasks + Google Calendar. Своего сервера с задачами нет (бот хранит только снимок на неделю для напоминаний).
- Поля Спутника (колонка, тип, приоритет, время, привычки, сферы…) — «слой», JSON на компьютере + копия в appDataFolder Google Drive, слияние по записям по времени `t`, удаление — надгробие `{ gone: true, t }`. Rust-версия пишет только в `%APPDATA%\com.siponik.sputnik\rust\`, старые файлы трекера только читает.
- Привычки — задачи списка «Привычки» в Google Tasks, расписание и история — в слое.
- Задачи со временем не дублировать событиями в Google Календаре — напоминаний через бота достаточно.
- Поля «Софт» и «Полигонаж» не нужны.
- Вид — «Система G» (`docs/design-g.md`): ноды с цветными шапками по сферам, провода, строгость чертежа, Onest + JetBrains Mono, акцент `#F0A04B`, тёмная тема основная.
- Енота в Rust-версии нет: на его местах — знак спутника на орбите, цвет по состоянию (`docs/design-g-fixes.md`).
- Общие сферы — свой Google Календарь на сферу, владелец делится по почте (`docs/shared-sphere.md`).
- Общий ключ Google встраивается в сборку из секрета `GOOGLE_CLIENT_JSON`; `client_secret.json` у пользователя никогда не коммитить и не выводить. Ключ подписи обновлений `TAURI_SIGNING_PRIVATE_KEY` потерять нельзя.
- Приложение для других людей (до 100 человек без проверки Google).
