# Спутник · задачи из любого чата

У Claude нет прямого подключения к Google Tasks. Задачи передаются через календарь-очередь:
Claude создаёт в нём событие с JSON-запросом в описании, а скрипт Спутника (Google Apps Script)
раз в минуту выполняет запрос в Google Tasks и удаляет событие. Задача появляется в течение ~1–2 минут,
даже если компьютер пользователя выключен. Поля Спутника (`layer`) трекер забирает при ближайшей синхронизации
(раз в 2 минуты, пока трекер открыт).

- Календарь-очередь «Спутник · входящие». Его `calendarId` найди через `list_calendars` по названию
  (вида `…@group.calendar.google.com`); если календаря нет — скажи, что Спутник ещё не подключён к «Входящим».
- Статус — событие «Спутник · статус» в этом же календаре, 1 января 2030 года. В его описании JSON:
  `lists` (точные названия списков), `processed` (итоги последних запросов: `ok`, `error`, `created`).

## Как отправить запрос

1. Если нужен существующий список — сначала прочитай статус (`list_events` по этому `calendarId`,
   с 2030-01-01 по 2030-01-02) и возьми точное название из `lists`. Похожее название («тауэр», «разработка»)
   сопоставь с существующим списком; новый список создавай, только если подходящего нет или пользователь так сказал.
2. Создай событие (`create_event`):
   - `calendarId` — из блока выше;
   - `summary` — коротко, например `＋ Купить кисти`;
   - `startTime` — сейчас (местное время без смещения), `endTime` — +15 минут;
   - `useDefaultReminders: false`, `notificationLevel: NONE`, `availability: AVAILABILITY_FREE`, без участников и Meet;
   - `description` — только JSON по формату ниже, без пояснений вокруг.
3. Ответь одной строкой: «Отправил в Спутник — появится в «Список» через минуту-две».
   Не проси подтверждений и не пересказывай JSON.

## Формат запроса

```json
{
  "sputnik": 1,
  "id": "req-20261019-1455-a1b2",
  "from": "chat",
  "ops": [
    { "op": "list.ensure", "list": "Lookout Tower", "layer": { "template": "asset3d", "view": "pipe", "sphere": "3D" } },
    { "op": "task.create", "list": "Lookout Tower", "title": "Блокаут башни", "notes": "…", "due": "2026-10-23",
      "layer": { "status": "blockout", "priority": 1, "type": "creative", "slot": { "s": "17:00", "e": "19:00" }, "remind": [60] } }
  ]
}
```

- `id` — `req-ГГГГММДД-ЧЧММ-` + 4 случайных латинских символа/цифры; новый для каждого запроса.
- `from` — откуда запрос: `chat`, `phone`, `morning-brief` и т. п.
- Операции (другие не принимаются, удаления нет):
  - `list.ensure {list, layer?}` — создать список, если его нет; `layer` — поля списка (ниже);
  - `task.create {list, title, notes?, due?, parent?, done?, layer?}` — список создаётся сам, если его нет;
    `due` — `ГГГГ-ММ-ДД` или не указывать (время — в `layer.slot`);
    `parent` — точное название открытой задачи в этом списке, чтобы сделать подзадачу (родителя можно создать в том же запросе раньше);
    `done: true` — сразу выполненная (для примеров и истории);
  - `task.complete {list, title}` — отметить выполненной (точное название открытой задачи).
- Ограничения: `title` до 250 символов, `notes` до 4000, `layer` до 1500, не больше 30 операций в одном запросе.
  Несколько задач сразу — одним событием с несколькими `task.create`.

### Поля списка (`list.ensure` → `layer`)

Применяются один раз после запроса; на существующем списке тоже работают (сменить вид, перенести в сферу).

- `template` — шаблон доски, id или название. Встроенные и их колонки (id → название):
  - `work` «Работа», канбан: `inbox` Входящие · `doing` В работе (лимит 3) · `review` На ревью · `done` Готово;
  - `client` «Заказы клиентов», канбан: `request` Заявка · `estimate` Смета · `doing` В работе · `revise` Правки · `delivered` Сдано · `done` Оплачено; у задач есть клиент и сумма;
  - `asset3d` «3D-ассеты», конвейер: `refs` Референсы · `blockout` Блокаут · `sculpt` Скульпт · `retopo` Ретопология · `uv` UV · `textures` Текстуры · `render` Рендер · `done` Готово;
  - `personal` «Личное», стикеры: `inbox` Надо сделать · `doing` Делаю · `done` Готово;
  - `study` «Учёба», список: `inbox` В планах · `doing` Прохожу · `done` Пройдено.
  Свои шаблоны пользователя — по названию. Без шаблона список — «Работа».
- `view` — вид доски: `kanban`, `pipe` (Конвейер), `stickers`, `list`. Без него — вид шаблона.
- `sphere` — название сферы (группа списков слева). Нет такой — создаётся; `sphereColor` — `clay`, `gold`, `work` (синий),
  `study` (фиолетовый), `personal` (зелёный), `done` (бирюзовый); `sphereIcon` — `cube`, `case`, `book`, `home`, `users`, `heart`, `brush`, `star`.
- `topics` — темы стикеров: `["Покупки", {"name": "Кот", "color": "study"}]`. Без них — Документы, Покупки, Звонки, Здоровье, Дом.
- `group` — раскладка стикеров: `topic` (по темам) или `when` (по срокам).

### Поля задачи (`task.create` → `layer`)

- `status` — колонка канбана или этап конвейера (id из шаблона списка; `done` не ставь — для этого `done: true`);
- `priority` — 1 высокий, 2 средний, 3 низкий;
- `type` — `work`, `creative` (3D/арт), `study`, `personal`, `meeting`, `plain`;
- `slot` — время `{ "s": "17:00", "e": "18:00" }` (на день `due`; без конца — +1 час);
- `repeat` — `{ "every": "day" | "weekdays" | "week" | "month" | "year" }` (повтор от срока);
- `remind` — напоминание в Telegram за N минут до начала: число или массив (`0` — в момент начала, `60`, `1440` — за день).
  Без поля — напоминание пользователя по умолчанию;
- `topic` — тема стикера (название или id; новой темы нет — добавится к списку), `pin: true` — закрепить стикер;
- `client`, `money` — клиент и сумма (для «Заказов клиентов»), сумма строкой: `"45 000 ₽"`;
- `stage` — у подзадачи в конвейере: этап, к чек-листу которого она относится;
- `spent` — минут уже потрачено (учёт времени);
- `project`, `tags[]` — проект и теги;
- `accept: true` — не спрашивать «Принять / Отклонить» во «Входящих от Claude». Ставь, только когда пользователь
  прямо попросил создать набор задач (тестовые данные, план из чата) — обычная задача из разговора идёт без него.

## Много задач

- В одном запросе — до 30 операций, но задач с `layer` лучше не больше 20: поля ждут трекер в статусе ограниченного размера.
- Большой набор (сфера с несколькими списками) — по запросу на список, с паузой 2–3 минуты, пока трекер открыт.
  Сначала `list.ensure` с полями списка, потом задачи; подзадачи — после родителя.
- Для наглядного примера разнообразь: сроки сегодня / на неделе / без срока / просрочено (`due` в прошлом),
  все колонки или этапы, приоритеты, время, повторы, подзадачи, заметки, пара выполненных (`done: true`).

## Правила

- Срок ставь, только если пользователь его назвал («к пятнице» → ближайшая пятница). Не выдумывай заметки.
- Название задачи — короткое действие («Сменить пароль ArtStation»), детали — в `notes`.
- Колонку, тему, сферу выбирай по смыслу списка; не знаешь шаблон списка — не ставь `status`.
- Если пользователь спрашивает «дошло ли?» — прочитай статус и найди свой `id` в `processed`.
  `ok: false` → перескажи `error` простыми словами и предложи исправленный запрос.
  Событие с ошибкой остаётся в очереди с «⚠» в названии — его можно удалить после исправления.
- Пользователь общается по-русски, коротко, на «ты».
