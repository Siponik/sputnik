# Знания — база знаний в Спутнике (план, 05.11.2026)

Новый раздел нового приложения (`app/`, Flutter, дизайн G): свои заметки, референсы, конспекты, лор DND и 3D-техники
прямо в Спутнике, с быстрым поиском и графом связей «как в Obsidian». Решения пользователя 05.11:

- делаем **в новом приложении** (Flutter), не в старом трекере;
- главное — **граф из заметок** и наглядность; в стиле G граф вблизи превращается в ноды с проводами;
- только **открытые форматы и локальные файлы**: данные должны пережить любую замену программы;
- готовое берём из открытых проектов, где лицензия это позволяет (см. «Что берём готовым»);
- макеты нарисованы в треде дизайна и одобрены 05.11 (13 экранов `design/system-g/screens/G_Notes*.dc.html`, описание — раздел «Знания» в `docs/design-g.md`); этот документ задаёт поведение;
- по правилу проекта «одна фича — один PR» весь раздел делается одним PR в `beta`, шаги ниже — коммиты в нём.

## 1. Данные

- **Источник правды — папка Markdown-файлов** на диске пользователя. Одна заметка = один `.md`.
- Свойства — в шапке YAML (frontmatter): `type`, `tags`, `created`, `sputnik-task`, любые свои поля (`где`, `статус`, `фракция`…).
- Ссылки `[[Название]]`, `[[Название|подпись]]`, `[[Название#Раздел]]`, картинки `![[файл.png]]` — как в Obsidian, Logseq, Foam,
  SilverBullet: ту же папку можно в любой момент открыть другой программой.
- Теги — `#тег` в тексте и `tags:` в шапке.
- Вложения — папка `Вложения/` (имя настраивается).
- Папки повторяют сферы: `00 Входящие`, `3D`, `DND`, `Работа`, `Учёба`, `Личное`, `Шаблоны`. Цвет папки = цвет сферы.
- Холсты (свои схемы из заметок) — файлы `.canvas` в открытом формате **JSON Canvas** (jsoncanvas.org, MIT): Obsidian открывает их же.
- Первая папка — уже существующее хранилище пользователя (`Obsidian-Vault`, разделы DND и 3D), подключается как есть.
- **Индекс** (для поиска и графа) — только в папке настроек приложения, не в папке заметок; всегда пересобирается из файлов.
  Начинаем с индекса в памяти + файл-кэш JSON (соответствует правилу «JSON без базы» из `docs/flutter-architecture.md`).
  SQLite с полнотекстовым поиском — только если на тысячах заметок станет медленно (новый пакет, отдельное решение).
- **Синхронизация между компьютерами — встроенная, через Google Drive (решение 05.11)**, без программы «Google Диск
  для компьютера» и без git. Как с картинками задач сейчас: Спутник сам кладёт всё в папку **«Спутник / Знания»** на Drive
  пользователя (обычная видимая папка, право `drive.file` уже есть во входе). Локальная папка на компьютере — рабочая копия,
  с ней работает редактор и индекс; Drive — общая копия для второго компьютера и (позже) телефона.
  - Правило: заметка = файл на Drive с тем же путём; сверка по хешу и времени изменения; изменилось только с одной
    стороны — копируем; изменилось на обеих — **конфликт: сохраняются обе копии** («… (с другого компьютера).md»), ничего не
    затирается; удаление — в корзину Drive, а не насовсем.
  - Вложения (картинки) — тоже файлами в той же папке.
  - Первый запуск на втором компьютере: выбрать пустую папку → Спутник скачивает всё с Drive.
  - Без связи всё работает локально, отправка — когда связь появится (очередь, как у задач).
  - Место на Drive основного аккаунта бывает на исходе (20.10 освобождали): заметки весят мало, но картинки-референсы —
    много; Спутник показывает, сколько занято, и предупреждает, если Drive полон.

**Бережность к файлам (обязательно):** приложение меняет файл только по действию пользователя; при правке свойства в таблице меняется
одна строка шапки, остальное — байт в байт; переименование заметки предлагает обновить ссылки в других файлах и показывает, сколько
файлов изменится; удаление — в папку `.trash` внутри папки заметок (как у Obsidian, оттуда можно вернуть); если файл изменили снаружи, пока он открыт, — не затираем, а предлагаем выбрать.
Содержимое заметок не уходит никуда, кроме папки «Спутник / Знания» на Drive самого пользователя (ни в слой, ни в календари, ни боту).

## 2. Главные функции

**Основа (без неё раздела нет)**
1. Подключить папку (одну или несколько), увидеть дерево папок с числом заметок.
2. Список заметок папки: сортировка «изменено / А–Я / по числу связей», фильтр.
3. Редактор Markdown: правка и «Чтение», подсветка заголовков, списков, `[[ссылок]]` (несуществующие — пунктиром),
   `#тегов`, чек-листов; автосохранение; подсказка названий при вводе `[[`.
4. Свойства заметки — серая плашка над текстом (как в окне задачи): тип, теги, связанная задача, свои поля.
5. Новая заметка (в т. ч. из шаблона папки `Шаблоны`), переименование, перенос в другую папку, удаление.
6. Картинки: вставка перетаскиванием и Ctrl+V в `Вложения/`, превью в тексте.
7. Слежение за папкой: правки в другой программе видны сразу.

**Связи и граф (главное для пользователя)**
8. Панель «Связи»: «Ссылается на», «Ссылаются сюда» (с куском текста вокруг ссылки), «Упомянуто без ссылки» с кнопкой «Связать»,
   несуществующие заметки с кнопкой «Создать».
9. Локальный граф заметки (глубина 1–3).
10. **Граф знаний**: вся база, раскладка сил (отталкивание, пружины связей, притяжение к центру — настраиваются ползунками),
    цвет — по папке/сфере, размер — по числу связей, наведение подсвечивает соседей, фильтры (папки, теги точками, вложения,
    заметки без связей, ещё не созданные), поиск по графу, перетаскивание точек, масштаб колёсиком.
11. **Граф вблизи (идея G)**: при приближении точки плавно раскрываются в ноды G (шапка цвета папки, первые строки, теги),
    ссылки становятся проводами с сокетами; выбранная — главная нода с уголками.
12. **Холст**: свои схемы из заметок (кампания DND, пайплайн ассета) — ноды-заметки, текстовые карточки, картинки, группы-рамки,
    провода с подписями; файл `.canvas`. Тянуть заметку из списка на холст.

**Наглядность**
13. Вид «Карточки» — для референсов: крупная картинка + полоска картинок заметки, теги.
14. Вид «Таблица по свойствам» — колонки из шапок заметок, фильтр «тип: НПС», правка ячейки, «＋ строка» = новая заметка с этими свойствами.

**Поиск**
15. Ctrl K находит и заметки (группа «Заметки» с куском текста), поиск по началу слов, ё = е, «＋ Новая заметка «…»».
16. Поиск внутри раздела: по тексту, тегу, свойству.

**Связь со Спутником**
17. Задача ↔ заметка: в окне задачи блок «Заметки» («＋ Связать»), в заметке свойство `sputnik-task`.
18. Выделить строки `- [ ]` → «Создать N задач в Спутнике» (тот же путь, что окно «Создать»).
19. Бот: `/note текст` и пересланное сообщение → заметка в `00 Входящие` (бот кладёт в очередь `GET /inbox`, приложение пишет файл).

**Позже (не сейчас):** смысловой поиск на локальных моделях, публикация заметок, совместные заметки в общих сферах.

## 3. Требования к экранам (для треда дизайна)

Все — в системе G, вкладка шапки «ЗНАНИЯ» пятой. Макеты нарисованы в треде дизайна (страница холста «Знания», PR #113), одобрены 05.11.

   с вкладками (несколько открытых заметок), свойства в одну строку, текст, внизу блок «Ссылаются сюда».
   Кнопка «↔ Связи» открывает отдельный экран **Связи** (полная панель связей и локальный граф). Решение 05.11 после
   комментария пользователя: пять колонок — слишком тесно. Макеты — `design/system-g/screens/G_Notes.dc.html`,
   `G_NotesLinks.dc.html` и остальные `G_Notes*.dc.html`, описание — раздел «Знания» в `docs/design-g.md`.
2. **Граф знаний** — нода «Фильтры» (поиск, «Весь | Локальный», группы по цвету, переключатели, ползунки сил), граф на холсте
   с точками, карточка выбранной заметки (Enter — открыть, L — локальный), масштаб, штамп листа.
3. **Граф вблизи** — те же данные при приближении: ноды и провода, несуществующая заметка — пунктирная нода «Создать».
4. **Холст** — панель (＋ Заметка / Текст / Картинка / Группа, авто-раскладка), группы-рамки, подписи проводов.
5. **Карточки** — сетка карточек с картинками; переключатель «Список | Карточки | Таблица | Граф».
6. **Таблица по свойствам** — колонки-свойства, условия-чипы, правка ячейки.
7. **Поиск Ctrl K** с группой «Заметки»; **окно задачи** с блоком «Заметки» и «Создать задачи из `- [ ]`»; захват из бота.
8. Состояния: первый запуск раздела («Выбери папку с заметками» / «Создать новую»), пустая папка, файл изменён снаружи,
   конфликт имён, папка недоступна, идёт индексация («Читаю 152 заметки…»); синхронизация с Drive (строка в «Состоянии»: «Знания: всё отправлено / отправляю 3 / нет связи»), конфликт (две копии рядом и «Оставить эту / Оставить обе»), Drive полон.
9. Окна: подключение папки, переименование с обновлением ссылок, выбор шаблона новой заметки.

## 4. Что берём готовым

Репозиторий без файла лицензии (по умолчанию «все права у автора»), поэтому код берём только из проектов с разрешающими
лицензиями (MIT, BSD, ISC, Apache) и указываем источник в шапке файла. Из AGPL/GPL (GitJournal, Logseq) и MPL/AGPL (AppFlowy) —
только идеи, без копирования кода.

| Что | Откуда | Лицензия | Как |
|---|---|---|---|
| Разбор Markdown, своё правило для `[[ссылок]]` | пакет `markdown` (dart-lang) | BSD-3 | пакет |
| Шапка YAML | пакет `yaml` (dart-lang) | MIT | пакет |
| Слежение за папкой | пакет `watcher` (dart-lang) | BSD-3 | пакет |
| Раскладка графа | d3-force (velocity Verlet, Barnes–Hut, link/charge/center/collide) | ISC | переносим алгоритм на Dart в `core/` с тестами — готовые пакеты на pub.dev (например, `force_directed_graphview`) считают O(N²) и медленны на больших графах |
| Рисование графа | свой `CustomPainter` + `InteractiveViewer` (Flutter) | — | ноды G и так рисуем сами |
| Жесты графа (перетаскивание, наведение) | `flutter_force_directed_graph` | BSD-3 | смотрим как образец |
| Редактор с подсветкой | `re_editor` | MIT | пакет или образец (обычный редактор кода, подсветку Markdown делаем сами) |
| Правила ссылок, обратные ссылки, «упомянуто без ссылки», заглушки | Foam | MIT | правила и тест-кейсы |
| Индекс и запросы по свойствам | SilverBullet | MIT | идеи |
| Похожее приложение на Flutter (граф на `graphview`, Markdown) | Ozan | MIT | образец устройства, код по месту |
| Формат холста | JSON Canvas | MIT | формат файла `.canvas` |
| SQLite + FTS5 (если понадобится) | пакет `sqlite3` | MIT | пакет, позже |

Новые пакеты добавляются в `app/pubspec.yaml` только в своём шаге и с проверкой сборки под Windows (правило из `docs/flutter-architecture.md`).

свойств и теги, частые сверху), «＋ Заметка». Карточки — обложка из первой картинки (`imagesOf`), «N фото», теги. Таблица —
колонки из шапок (`propColumns`: тип первым, потом по частоте), сортировка по клику (`sortDocs`: числа как числа, пустые внизу),
правка ячейки — `setProp` (меняется только эта строка шапки), «＋ Новая строка» — заметка с условиями в шапке (`frontFromConds`).
Логика — `core/notes/folder_view.dart`.
Шаг 12 — холст `.canvas` (JSON Canvas 1.0, тот же файл открывает Obsidian): `core/notes/canvas.dart` (`CanvasDoc` — разбор,
неизвестные поля сохраняются как были, битые записи пропускаются; `add`/`remove`/`connect`/`inside`/`hit`/`bounds`,
«Авто-раскладка» — `ForceSim`, группы стоят, шаг 10), экран `ui/notes/canvas_view.dart`: открывается вкладкой как заметка (в дереве — «▦»,
«▦» рядом с «＋» — новый холст), «＋ Заметка» (поиск) или перетащить заметку из дерева, «＋ Текст» (и двойной клик по фону),
«＋ Картинка» (в `Вложения/`), «Группа»; тянуть ноду (группа — вместе с тем, что внутри), сокеты по сторонам — провод, уголок — размер,
двойной клик — правка текста или подписи провода, Delete — убрать. Сохранение — `NotesState.canvasChanged` через ту же задержку;
изменили снаружи — своя версия ложится рядом копией, на экране — диск (`canvasNotice`). Битый файл не перезаписывается (`canvasErrors`).
Шаг 13 (в новом приложении пока нет окна задачи и своего бота — сделано то, что от них не зависит): «⋯ → Чек-лист → в задачи · N» —
пункты `- [ ]` заметки (ссылки — подписью) уходят задачами в выбранный список Google Tasks, в описании задачи — «Из заметки «…» · путь».
Файл заметки не меняется: отправленное помнит `notes.json` (`config.sent`, `todoKey`), второй раз пункт не уйдёт, при ошибке ушедшие
сохраняются. Связь с приложением — `NotesState.tasks` (`TaskSink`: списки и `AppState.addTask` → `GoogleApi.createTask`). Для блока
«Заметки» в будущем окне задачи готов `core/notes/tasks.dart` `notesAbout(индекс, название)` (заметка с таким названием, ссылка на неё,
название целым словом; ё = е). Осталось на потом: сам блок в окне задачи (когда окно появится в новом приложении) и `/note` в общем боте —
боту нужна запись в папку на Drive пользователя, а ключей Google на сервере бота нет (решение 22.10), так что это — через очередь, как задачи.
