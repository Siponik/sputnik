# Спутник на Flutter: архитектура и правила переноса

Этот документ — главный для всех, кто пишет новое приложение (в том числе для более простых моделей, которым передаётся
перенос по заданиям). Читать целиком перед первым заданием. Если правило здесь и в задании расходятся — прав документ;
если документ молчит — не выдумывай поведение, спроси или оставь пометку `// TODO(вопрос): …` и напиши об этом в PR.

## 1. Цель и границы

- Переписать трекер (`tracker/`, Tauri + Svelte) на **Flutter** (Dart): отклик «как у родной программы», один код на
  Windows и (позже) Android, новый дизайн G (ноды со строгостью чертежа).
- Новое приложение живёт в папке **`app/`**. Старый трекер **не трогаем и не удаляем**, пока новый не дойдёт до паритета.
  Всё, что происходит с данными, должно оставаться совместимым: тот же слой `layer.json`, те же задачи в Google Tasks,
  те же служебные события в календарях, тот же формат общих сфер, тот же бот.
- Не меняется: облачный бот (`bot/`), Apps Script (`reminders/`), утренние новости, GitHub-конвейеры.
- **Поведение берём у старого кода**, а не придумываем. Источник истины, пока идёт перенос, — JS в `tracker/src/lib/*.js`
  и его тесты в `tracker/tests/`.
- Правила проекта: каждое изменение — PR в ветку **`beta`**, одна часть — один PR, в PR раздел «## Что нового» (если PR
  меняет то, что видит пользователь; для внутренних частей пиши «Внутренняя часть нового приложения, пользователю пока не видна»).

## 2. Стек

| Что | Выбор | Почему |
|---|---|---|
| Язык / каркас | Dart 3.13, Flutter 3.47 (stable) | версия закреплена в `app/pubspec.yaml` и в `.github/workflows/app-check.yml` |
| Состояние | `flutter_riverpod` (`Notifier`, `AsyncNotifier`) | заменяет сторы Svelte; простой тест без экрана |
| Сеть | `http` + свой тонкий клиент Google REST | API Tasks/Calendar/Drive — простые JSON-запросы |
| Вход в Google | OAuth для настольных приложений (loopback + PKCE), как в `google.rs` | тот же ключ и те же доступы; токен хранится рядом с данными |
| Хранение | **JSON-файлы**, без базы данных | слой уже JSON, данных сотни записей, а не миллионы; файл + память мгновенны |
| Папки / окно / системное | `path_provider`, `window_manager`, `flutter_local_notifications`, `flutter_svg`, `url_launcher` | подключаем по мере нужды |

Новые пакеты добавлять только по заданию или после согласования: каждый пакет — риск для сборки под Windows и Android.

## 3. Слои (порт схемы из `docs/architecture.md`)

```
app/lib/
  core/    чистая логика на Dart: правила, расчёты, разбор текста, слияние. Ни Flutter, ни dart:io, ни сети.
  data/    файлы, Google REST, синхронизация, вход. Знает core, не знает экранов.
  state/   Riverpod-контроллеры: состояние приложения и действия над ним. Зовут core и data.
  ui/      виджеты и экраны. Показывают состояние, зовут действия. Не зовут data напрямую, не держат правил.
  main.dart
app/test/
  core/    тесты логики (в том числе «золотые»)
  golden/  JSON-файлы с входами и ответами старого кода (генерируются, см. п. 4)
```

Правило зависимостей (стрелка — «может импортировать»): `ui → state → data → core`, `state → core`. Обратно — нельзя.
**Экран показывает, контроллер решает, core считает, data достаёт.**

Чеклист новой функции: расчёты и правила — в `core/` с тестом; действия и состояние — в контроллере; виджет только показывает.

## 4. Как переносится логика (золотые тесты)

Каждый модуль логики из `tracker/src/lib/*.js` переносится так:

1. Найти все чистые функции модуля (без Svelte, сети, Tauri). Сетевые части (`gapi`, Drive) — не в core, а в `data/` (отдельное задание).
2. Дописать входы в **`tools/golden/gen.mjs`**: он запускает настоящий JS и пишет входы с ответами в `app/test/golden/<имя>.json`
   (запуск из корня репозитория: `node tools/golden/gen.mjs`; файлы коммитим). Входы — это примеры из старых тестов
   `tracker/tests/<имя>.test.js` **плюс** граничные случаи (границы месяцев и года, пустые значения, русский регистр,
   дубликаты) **плюс**, где это уместно, случайные входы с фиксированным seed (см. `layer_merge`).
3. Написать Dart-версию в `app/lib/core/<имя>.dart`: те же имена функций (lowerCamelCase), те же правила, комментарий-шапка
   со ссылкой на JS-файл.
4. Написать `app/test/core/<имя>_test.dart`: читает golden-файл и требует **те же ответы**.
5. `cd app && flutter analyze && flutter test` — всё зелёное.

Образцы: `core/when.dart` ↔ `tracker/src/lib/when.js`, `core/layer.dart` ↔ `tracker/src/lib/layer.js`.

Готово, когда: golden-тесты зелёные, `flutter analyze` без замечаний, в шапке файла указан JS-источник, в `docs/flutter-tasks/README.md`
в таблице стоит ✅.

### Подводные камни JS → Dart (уже наступали)

- **Месяцы.** В JS `new Date(y, m, d)` — `m` от 0 до 11, в Dart `DateTime(y, m, d)` — от 1 до 12. Это уже давало баг в `when.dart` (поймали золотым тестом).
- **Дни недели.** JS `getDay()`: вс = 0; Dart `weekday`: пн = 1 … вс = 7.
- **Выход за границы даты** (`new Date(2026, 1, 31)`) и в JS, и в Dart сдвигается на следующий месяц — работает одинаково, не «чинить».
- **«Истина» в JS.** `if (x)` истинно не только для `true`: 0, `''`, `null`, `undefined` — ложь. В Dart `if` принимает только `bool`: пиши явную проверку (см. `_truthy` в `layer.dart`).
- **`undefined` и `null`.** В JSON-слое «ключа нет» и «ключ равен null» — разные вещи; различай через `containsKey`.
- **Сравнение строк** в JS и `compareTo` в Dart идут по кодам UTF-16 — совпадают. `JSON.stringify` и `jsonEncode` сохраняют порядок ключей.
- **Регулярки.** Синтаксис почти тот же; пиши `RegExp(r'…')` (сырая строка), флаг `/i` → `caseSensitive: false`. `String.replace(строка, …)` в JS заменяет первое вхождение → `replaceFirst`. `match` с группами → `firstMatch`, группа без совпадения — `null`.
- **Числа.** В JS всё `number`; в JSON из Dart целые — `int`, дробные — `double`. Сравнивай через `num`.
- **Сортировка.** `Array.sort` в JS устойчивая, `List.sort` в Dart — **нет**. Если порядок равных элементов важен, добавь второй ключ сортировки (индекс).
- **Время и пояса.** Держим местное время, как в старом коде; тесты запускаются с `TZ=Europe/Moscow` (так в CI).

## 5. Данные: «сначала локально»

Именно это даёт отклик. Правила:

1. Источник правды для экрана — **состояние в памяти** (контроллеры), оно же сохраняется в файлы в папке данных приложения.
   Экран никогда не ждёт Google.
2. Любое действие (отметить, перенести, создать…) делает три вещи сразу: меняет состояние в памяти → пишет файл (с небольшой
   задержкой, одним куском) → кладёт операцию в **очередь исходящих** (`data/outbox`).
3. Фоновый цикл синхронизации берёт очередь по порядку и отправляет в Google. Успех — операция удаляется. Ошибка сети —
   операция остаётся, цикл повторит позже (интервалы растут). Ошибка «запретили» (403/404) — откат в состоянии и плашка
   «Не получилось…» с «Повторить» (как «Не сохранилось · Повторить» в старом окне задачи).
4. Входящие изменения (опрос Google раз в 2 минуты, по фокусу окна) не затирают правки, сделанные пока шёл запрос
   (аналог `lib/fresh.js` `keepLocal`).
5. **Слой** (`layer.json`) — тот же формат и то же слияние по записям, что в старом приложении (`core/layer.dart`),
   облачная копия — файл `sputnik-layer.json` в appDataFolder на Drive. Надгробия `{ gone: true, t }` вместо удаления.
6. Папка данных: Windows `%APPDATA%\com.siponik.sputnik` — **та же, что у старого приложения**, чтобы они делили слой и токен
   на время перехода (формат файлов не менять!). Пока идёт перенос, новое приложение при первом запуске **только читает**
   существующие файлы, а пишет в отдельную подпапку `flutter/`; переход на общую запись — отдельное решение с пользователем.
7. Резервные копии слоя — как `backup.rs`: раз в день перед первой записью, хранить 14.

## 6. Дизайн G

Описание и макеты дизайна G добавляются в репозиторий отдельным тредом (`docs/` и `design/`). До этого момента UI — только
каркас и заглушки; не придумывай внешний вид самостоятельно. Правила для виджетов уже сейчас:

- Ни одного жёстко прописанного цвета, размера отступа, радиуса, длительности анимации или шрифта внутри виджетов. Всё идёт из
  токенов: `app/lib/ui/theme/` (`SpColors`, `SpSpacing`, `SpType`, `SpMotion`) — файлы появятся вместе с дизайном G.
- Анимации — только через `SpMotion` (там же уровни «полные / минимум / выкл» из настроек).
- Каждый экран — отдельная папка `app/lib/ui/<экран>/`, общие виджеты — `app/lib/ui/widgets/`.
- Знак, енот-космонавт и иконки — SVG из `design/mascot/`, подключаются как assets через `flutter_svg`.

## 7. Карта переноса и порядок (волны)

Каждая волна — набор заданий (`docs/flutter-tasks/`), каждое задание — один PR в beta.

- **Волна 0. Основа** ✅: папка `app/`, CI, золотые тесты, `core/when`, `core/layer` (слияние), `core/dates`.
- **Волна 1. Чистая логика (`core/`)**: остальные модули с таблицей в `docs/flutter-tasks/README.md`. Параллельно, независимо друг от друга.
- **Волна 2. Данные (`data/`)**: вход в Google (loopback + PKCE), клиент REST (Tasks, Calendar, Drive), файловое хранилище и резервные
  копии, очередь исходящих и цикл синхронизации, файл слоя на Drive.
- **Волна 3. Пробный каркас**: оболочка (окно, шапка, навигация), экран «Сегодня» на реальных данных. **Здесь решаем, идём ли дальше**
  (замер отклика, ощущение, стоимость).
- **Волна 4. Экраны** по одному: Доска (канбан → Конвейер → Стикеры → Список), Окно задачи, «Создать», Календарь, Привычки,
  Настройки, Шаблоны и редактор списка, Сферы, Поиск.
- **Волна 5. Остальное**: общие сферы, Входящие от Claude, бот (отправка снимка, очередь), напоминания и уведомления Windows,
  обновление приложения и бета-канал, упаковка (.msi или аналог), затем Android.

Работа на старом трекере не останавливается: пока старый живёт, исправления идут туда. Когда меняется поведение в JS-модуле,
который уже перенесён, — в том же PR обновить `tools/golden/gen.mjs`, перегенерировать golden и поправить Dart (иначе
`app-check` станет красным).

## 8. Задания для исполнителя

Файлы заданий — `docs/flutter-tasks/NNN-имя.md` по шаблону из `docs/flutter-tasks/README.md`. Правила исполнителя:

1. Одно задание — один PR в ветку `beta` (не в `main`), название по-русски понятным языком.
2. Трогать только то, что названо в задании: `app/…`, `tools/golden/gen.mjs`, `app/test/golden/`, `docs/flutter-tasks/README.md` (статус).
   В `tracker/`, `bot/`, `reminders/` ничего не менять.
3. Не добавлять пакеты, не менять версии, не менять `pubspec.yaml` без прямого указания.
4. Перед PR: `cd app && flutter pub get && flutter analyze && flutter test` — всё зелёное, приложить вывод в описание.
5. Не «улучшать» старое поведение. Нашёл ошибку в старом коде — не переноси молча и не исправляй молча: опиши в PR
   («в JS так, в Dart сделал так же, вот почему это выглядит неверно»).
6. Комментарии в коде — по-русски, коротко, объясняют «зачем». Имена — как в JS (lowerCamelCase для функций, UpperCamelCase для классов).

## 9. Запуск

На компьютере разработчика (Windows):

```
cd app
flutter pub get
flutter test
flutter run -d windows
```

Нужен Flutter 3.47.x и Visual Studio Build Tools 2022 с компонентом «Разработка классических приложений на C++».

## 10. Открытые вопросы

- Вход в Google на Windows: сделать свой loopback-вход или взять `googleapis_auth`. Решается заданием «Вход в Google» в волне 2
  (результат — короткая записка с причинами выбора).
- Автообновление и бета-канал: аналога `tauri-plugin-updater` нет; решить в волне 5 (WinSparkle через `auto_updater` или своя
  проверка `latest.json` + запуск установщика).
- Дизайн G (токены, нодовые виджеты, общий вид) — после появления в репозитории.
- Общая запись с Tauri-приложением в одну папку данных (см. п. 5.6) — решить перед волной 4.
