# «Входящие от Claude»: задачи в Google Tasks из любого чата

Цель: в любом чате с Claude (телефон, веб, приложение, утренняя сводка) сказать «создай задачу…»,
и через пару минут она появляется в Google Tasks: в нужном списке, со сроком и полями слоя Спутника.
Работать должно даже когда компьютер выключен.

## Почему так

- В чатах Claude есть подключения Gmail, Google Calendar и Google Drive. **Подключения к Google Tasks нет.**
- Подключение Drive умеет только создавать файлы и менять их название и описание. Содержимое существующего файла оно не перезаписывает,
  а наш ключ со скоупом `drive.file` не видит файлы, созданные не нашим приложением. Поэтому Drive как канал требует
  restricted-скоуп `drive` / `drive.readonly`. Это хуже.
- Подключение **Calendar** умеет `create_event` в **любом календаре по `calendarId`**, с описанием. Наш ключ уже имеет скоуп
  `calendar` и может читать и удалять события. **Канал = отдельный календарь-очередь.** Новых прав не нужно.

## Схема

```
Чат Claude ──create_event──▶ календарь «Спутник · входящие» (скрыт в интерфейсе Google)
                                   │
         обработчик (каждые 10 мин GitHub Actions; позже ещё и трекер раз в 2 мин)
                                   │  читает события → проверяет → создаёт списки и задачи
                                   ▼
                     Google Tasks  +  слой Спутника  +  событие удаляется
                                   │
                     файл-статус на Drive «Спутник · статус.json» (создаёт обработчик):
                     обработанные запросы, ошибки, названия списков — Claude читает его, чтобы знать списки и итог
```

## Формат запроса (одно событие = один запрос)

- Календарь: «Спутник · входящие» (создаёт bootstrap-скрипт; его `calendarId` записать в `CLAUDE.md` и в навык).
- `summary`: человекочитаемо, например `＋ Переделать енота`. Обработчик смотрит не на него, а на описание.
- Время: любое, удобно `startTime = сейчас`, длительность 15 мин, `useDefaultReminders: false`, без участников и Meet,
  `notificationLevel: NONE`.
- `description`: JSON (обработчик должен уметь вынуть JSON, даже если Calendar обернул его в HTML: снять теги, декодировать сущности).

```json
{
  "sputnik": 1,
  "id": "req-20261019-1455-a1b2",
  "from": "chat",
  "ops": [
    { "op": "list.ensure", "list": "Lookout Tower" },
    { "op": "task.create", "list": "Спутник · разработка",
      "title": "Переделать енота: голова должна помещаться в шлем",
      "notes": "…", "due": null,
      "layer": { "type": "creative", "project": "Спутник", "priority": 2, "tags": ["дизайн"], "stage": null } }
  ]
}
```

Операции v1 (только они, остальное — ошибка):
- `list.ensure {list}` — создать список, если нет.
- `task.create {list, title, notes?, due?(YYYY-MM-DD), parent?(название родительской задачи), layer?}` — список создаётся сам, если нет.
- `task.complete {list, title}` — отметить выполненной (точное совпадение названия среди открытых задач).

Удаления в v1 нет намеренно.

## Обработчик

1. `tools/inbox/process.mjs` (Node 18+, без зависимостей; вход — как в `tools/test-data/seed.mjs`, плюс режим CI:
   `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REFRESH_TOKEN` из переменных окружения).
2. Читает события календаря-очереди (`singleEvents`, за последние 30 дней и на 1 день вперёд).
3. Для каждого события: разобрать JSON → проверить схему (только разрешённые `op`, длины: title ≤ 250, notes ≤ 4000,
   ops ≤ 30) → выполнить → записать итог в статус → **удалить событие**. Невалидное событие не удалять,
   а переименовать в `⚠ …` и записать ошибку в статус, чтобы было видно.
4. Идемпотентность: `id` запроса пишется в статус до удаления события; перед `task.create` проверить, нет ли в списке
   открытой задачи с таким же названием, созданной за последние 2 дня (защита от двойной обработки трекером и Actions).
5. Слой: пока трекер не синхронизирует слой через Drive (шаг 2 плана), поля `layer` сохранять в статус-файл
   (`pendingLayer` по id задачи), а трекер при синхронизации переносит их в свой слой.
6. Статус-файл `Спутник · статус.json` на Drive (создаёт сам обработчик → доступен по `drive.file`): `updatedAt`,
   `lists[]` (названия), `processed{id: {ok, at, created[], error?}}` за 14 дней, `pendingLayer`. Подключение Drive у Claude
   его найдёт поиском и прочитает (`download_file_content` / `read_file_content`; проверить, какой работает для JSON).
   Если ни один не читает JSON — дублировать статус как Google-документ (`application/vnd.google-apps.document`).

`.github/workflows/claude-inbox.yml`: cron `*/10 * * * *` + `workflow_dispatch`, секреты `GOOGLE_CLIENT_ID`,
`GOOGLE_CLIENT_SECRET`, `GOOGLE_REFRESH_TOKEN`. При ошибке — комментарий в issue «CI: входящие от Claude» (как у сборки трекера).

## Важно про токен

Если проект Google Cloud в режиме **Testing**, refresh-токен живёт **7 дней** — в Actions всё сломается через неделю.
Нужно перевести OAuth consent screen в **In production** (без верификации, «непроверенное приложение» для себя — нормально;
скоупы tasks/calendar — sensitive, не restricted). Проверить статус в первую очередь и провести пользователя по шагам.

Как получить refresh-токен для секрета: `node tools/inbox/process.mjs --login` открывает вход и печатает
только инструкцию `gh secret set …` с чтением токена из файла, **не выводя сам токен в консоль/чат**.
Лучше: скрипт сам вызывает `gh secret set GOOGLE_REFRESH_TOKEN < .token.json`-аналог, если `gh` установлен.

## Навык для чатов Claude

После того как цепочка заработала — навык `sputnik-tasks` (через propose_skills), чтобы в любом чате Claude знал:
- когда пользователь просит задачу/список/«запиши»/«напомни сделать» → создать событие-запрос в календаре «Спутник · входящие»
  (calendarId из навыка), JSON по формату выше, `id` = `req-ГГГГММДД-ЧЧММ-4 случайных символа`;
- сначала прочитать статус-файл, чтобы взять точное название существующего списка;
- ответить коротко: «Отправил в Спутник, появится в «…» в течение ~10 минут»;
- не дергать пользователя подтверждениями, срок ставить только если он назван.
Утренняя сводка тоже может так добавлять задачи из писем (кнопка «В задачи»).
